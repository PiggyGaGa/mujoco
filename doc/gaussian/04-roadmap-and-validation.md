# 实施阶段与验收计划

> 更新：用户已于 2026-10-20 授权实施，首版现状与实测结果见 [实现记录](05-implementation.md)。下文保留原始设计/审计语境；“待授权”“拟议”不代表当前停止实施。

本计划需要用户后续指令启动。当前只完成设计文档和 skill，不执行下列代码修改。

## 阶段 0：固定基线

记录两个工程 HEAD、用户修改和依赖；确认缺失 CMake 的处理方式；原生 MuJoCo 与原 Splatapult 分别构建运行，保存基线截图/帧时。探测 GL version/profile、compute/SSBO、MSAA、sRGB 与 depth。任何不满足项先给出最小解决方案。

验收：能说明本机是否支持同上下文路线；无覆盖用户修改；基线问题与集成问题分开记录。

## 阶段 1：抽取渲染模块

形成不创建窗口、不管理输入的高斯渲染目标；资源路径独立于 cwd；上传/销毁归属 GL 线程；关闭高斯构建时普通 viewer 不受影响。

验收：已知的小高斯场景能在宿主上下文显示；加载失败能恢复；无 OpenXR/SDL 主循环要求。

## 阶段 2：原生相机与主视口

接入实际 mjvScene 相机，处理 near/far、非对称视锥、矩阵布局、UI rect 与 HiDPI。建立已知位置的几何/高斯标记。

验收：自由、固定、跟踪相机移动后标记持续重合；打开侧栏、resize 不偏移；不使用 Splatapult FlyCam 代替原相机。

## 阶段 3：深度合成

先做 framebuffer 深度复用验证，不通过则采用自有颜色/深度 FBO。几何先画，高斯按正确深度裁剪并透明混合，最后 UI。

验收场景：

| 场景 | 期望 |
|---|---|
| 高斯在不透明方块后 | 被方块遮住 |
| 半透明高斯在方块前 | 混合到方块颜色上 |
| 高斯与实体交错/移动 | 遮挡随视角稳定变化 |
| near/far 边缘 | 不出现错误穿透或整屏闪烁 |
| MSAA 默认/关闭、fp framebuffer | 深度定义一致或明确限制 |
| UI、坐标轴、曲线 | 按约定覆盖，不被高斯污染 |

截图不能证明严格体积正确；验收以当前 splat 近似为准。透明 MuJoCo geom 暂列未支持。

## 阶段 4：资产、变换与 UI

加入加载/卸载、显隐、配准与错误提示；保存独立 sidecar，不覆盖 PLY；显示世界坐标与实际 up 方向。文件替换期间物理和窗口继续可用。高阶 SH 随变换观察方向正确。

验收：普通点云/损坏 PLY 给出明确错误；SH0 与高阶 SH 均可验证；坐标/单位和碰撞代理可对照；重置物理不意外重置独立配准。

## 阶段 5：回归与性能

验证暂停、单步、控制、鼠标扰动、选取、模型重载、资产重载和退出；检查 GL 状态泄露、资源泄漏、重复释放。

分别记录 PLY 解析/上传时间、排序 GPU 时间、绘制 GPU 时间、整帧 CPU/GPU 时间、点数、分辨率、硬件、SH、内存峰值。静态相机缓存不能代替运动视角评测；开窗口 FPS 不等于训练吞吐。仅在测量支持时引入异步加载、缓存/LOD 等优化。

## 决策与主要风险

- D1：以 native C++ simulate 为第一目标，Python passive viewer 后续另行接入。
- D2：采用 Splatapult OpenGL 路径，不使用 MJWarp 替换 viewer renderer。
- D3：同上下文深度复用为优先探针，自有 FBO 为备选；由实测决定。
- D4：不修改物理引擎 ABI 或 MJCF schema；第一版以外部资产配置连接。
- D5：单目/静态高斯/不透明物体优先。stereo、透明排序、真实光照/阴影、拾取高斯不作首版承诺。
- 风险：GL 4.6 compatibility、投影/反向深度、GL 状态污染、线程生命周期、SH 旋转、大场景排序、碰撞代理误遮挡、资源路径与上游重构。

每阶段完成后记录实际证据与剩余限制；仅用户授权范围内推进，不因本文存在而自动开始实施。
